## 2. V1.1.4 · 判据方向（2026-11-24）

### 2.1 起因

用户报：「黄石—九江这条应该是绕飞，为什么还是禁止」。

排查结论：服务端 5xx=0、无 traceback。三处口径问题：

| 层 | 问题 |
|---|---|
| 判据 | `_risk()` 里 `if detour: risk += 0.18` —— 端点能见度 1.4 km 的基础分是 0.72（只到"提示"），一有绕飞就 0.90 → 判停飞，等于**"能绕的停、绕不开的反而放"** |
| 展示 | 详情标签与地图航迹按 `riskLevel` 染色，"绕飞放行"被涂成红底，读起来就是禁止 |
| 文案 | 航线悬停把 `borderBlocked`（越界封锁）写成"停飞"，和"绕飞/直飞"并列 |

另外两个真问题：真实天气下 `blocked_ids` 恒空（压线绕不开也能直飞放行）；0.8 km 侧移也判"绕飞成功"。

### 2.2 改了什么

| # | 改动 | 说明 |
|---|---|---|
| 1 | 绕飞不加风险分 | 代价改由 `detourKm` 与延误表达；风险分只回答"这条航路本身多危险" |
| 2 | 标签与航迹按 `decision` 染色 | HOLD 红 / DETOUR 琥珀 / RELEASE 绿 |
| 3 | `MIN_HIT_KM=3.0` | 航路与回波相交不足 3 km 视为擦边：不绕飞、不封锁 |
| 4 | `MIN_SHIFT_KM=3.0` | 只需偏 3 km 以内就能避开 → 返回 `negligible`，不建绕飞表、不封锁、按直飞算 |
| 5 | `_detour_table` 返回 `(table, blocked)` | 真实天气也产出封锁集合，与虚拟气象同一套判据 |
| 6 | 悬停文案 | 「越界封锁（不纳入）」 |
| 7 | `_VIRTUAL_CACHE` 上限 96 | 原来 144 档累积不回收 |

### 2.3 实测

| 班次 | 改前 | 改后 |
|---|---|---|
| NC-0211 遂宁→重庆 | risk 0.90 高 · 绕飞放行 | **0.72** · 绕飞放行 |
| NC-0038 南充→重庆 | risk 0.90 高 · 绕飞放行 | **0.72** · 绕飞放行 |
| NC-0212 邯郸→石家庄 | risk 0.90 · 绕飞 0.8 km | **不再记为绕飞**（擦边直飞） |

虚拟气象 m=120 的绕飞数 3 → 2，`delayed` 3 → 2。

### 2.4 护栏

`backend-python/tests/test_detour_verdict.py` 6 条 + `frontend/tests/detourVerdict.test.mjs` 4 条。
另修一个会假红的旧测试：版本一致性原先写死 `1.1.3`，改为以 `VERSION` 为基准。

## 3. V1.1.5 · 压力测试整改 + 运维（2026-11-24）

### 3.1 起因

用户要求"从用户/企业/研究院三个视角压力测试，找出隐藏 bug"。产出 `docs/压力测试与缺陷清单-20261124.md`（4 个 P1、4 个 P2、5 个 P3）。随后要求把原定 V1.2.0 的条目全部并入本版。

### 3.2 判据与数据（P1）

| # | 问题 | 改法 | 实测 |
|---|---|---|---|
| P1-4 | 时间轴首尾不是同一帧（0 是 124 架、1440 是 102 架） | `_norm_minute()`：`minute % 1440`，payload / flights / evidence 三入口 | 两者 traffic **完全一致** |
| P1-2 | 市层"在飞"只算始发，与"航线数（含进出港）"不同口径；辽宁 13 市里 11 个"航线>0、在飞=0" | `touch = origin + inbound`；另发 `airborneDeparting` 保留始发口径供上层对账 | 沈阳：12 条航线、**在飞 2（含飞入）**、始发 0 |
| P1-1 | 并发退化（原测 6 并发中位 5.2 s） | 载荷缓存 20 s + **single-flight**（同 key 只算一次，其余等结果） | 服务器内部 6 并发 **0.16–0.21 s** |
| P2-3 | 每帧 600 KB 全量重传、无缓存协商 | 强 ETag + `Cache-Control: private, max-age=20/10`；Java 补 304 分支（原先会掉进 `readValue("")` 抛 500） | `If-None-Match` 命中 → **304 / 0 字节** |
| 新 | **Java 双重 JSON 解析**：`readValue(600KB, Object.class)` 再序列化 | 新增 `decisionRaw`（`BodyHandlers.ofByteArray` + JSON/UTF-8 直出），trafficV2 与 nationFlights 改用它 | 单请求内部 0.035–0.062 s |
| P1-3 | 浏览器直连 `image.data.cma.cn` 必然被 CORS 拦（一次加载 8 条红字，后端 `/radar/tiles` 从未收到数据） | 显式关闭 `RADAR_RELAY_VIA_BROWSER=false`；中继入口只做结构检查（否则 10 条单测一起死） | console CORS 计数 **0** |

### 3.4 运维（同版第二批，`a25cbdd`）

| 项 | 内容 | 实测 |
|---|---|---|
| CPU 上限 | Java `CPUQuota=130%`、Python `110%`（2 核共享机，留余量给 nginx 与同机三个站点） | 部署后 Python **99.6% → 25%** |

### 3.5 一个必须记住的测量更正

原审计写"6 并发中位 5.21 s"，**主要是压测脚本没发 `Accept-Encoding`**（拉的是 617 KB 未压缩体）。补测：

| 场景 | 耗时 | 传输 |
|---|---|---|
| 服务器内部 单请求 | 0.035–0.062 s | — |
| 服务器内部 同帧 6 并发 | 0.16–0.21 s | — |
| 公网 + gzip（浏览器真实情况） | **0.45 s** | **112.9 KB** |

真正的成本是"整包重传"，不是锁。文档 §P1-1 已改写并保留更正痕迹。

### 3.6 没做的两项

| 项 | 决定 | 原因 |
|---|---|---|
| `GET /radar/tile` 同源代理 | ❌ 放弃 | 中继存在的唯一理由是"源站按 IP 封服务器、住宅网络浏览器能取"。同源代理仍从服务器出口出去，封 IP 时一样 403 —— 技术上无效 |
| nginx 层加安全头 | ❌ 改到应用内做 | 站点是"外层 443 + 内层 28081 + include 片段"三层，`add_header` 继承是"子级有则父级全失效"，有弄丢现有 `Cache-Control: no-store` 的风险 |

## 4. V1.1.6 · 打开就不用等（2026-11-24）

### 4.1 需求

> "先跑的这个文件（`_warmup_demo.py`）想办法在用户使用时自动运行；反事实这个想办法在使用时就直接先预加载，避免响应时间过长。"

### 4.2 改了什么

| 项 | 内容 |
|---|---|
| **预热搬进浏览器** | 新增 `frontend/src/traffic/prefetch.js`：`load` 后 4 秒、静默、串行，按 `constants → overview → nation/flights → 某在飞班次的 evidence → 反事实预建` 各拉一遍。`sessionStorage` 打标（一个标签页一次），失败一律吞掉 |
| **反事实预建** | 新增 `POST /api/traffic/v2/counterfactual/prewarm`：已 READY 直接返回；否则起**后台线程**建场，请求立刻回 `PREWARMING`；同一 `(seed, scenario)` **60 秒节流** → `THROTTLED` |
| 不做定时预建 | 计划 key 含 `radar_id` 与 `snapshot_id`，帧一动就重算；2 核机器上定时预建等于常年 25% CPU 空转。只在"有人真要打开"时建 |
| 配套 | Java 加 `@PostMapping` 白名单（必须给 `Map.of()` 当 body，否则 `decisionRequest` 落 GET 分支 → 405）；`main.py` 的 `threading` 提升到模块级 |

### 4.3 实测

| 调用 | 结果 |
|---|---|
| prewarm 首次 | `PREWARMING`，3.36 s 返回 |
| prewarm 3.6 s 后 | `THROTTLED`，0.24 s |
| `GET counterfactual` 预建前 | `BUILDING`，114 B |
| **`GET counterfactual` 预建 60 s 后** | **`status=OK`，5764 B，0.99 s** |

前端预取（nginx 日志，一次页面打开）：`constants` / `overview` / `flights` / `evidence` / `prewarm` 全部按序发出。
